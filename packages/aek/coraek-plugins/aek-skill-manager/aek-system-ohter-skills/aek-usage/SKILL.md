# aek-usage

- AEK 系统原生内置隔离实例。
- 当 AI 想开发 AEK 从内到外的任何东西时，如果聪明的话，它自己会启动一个 **AEK Next** 实例，从而维持原来的 AEK 实例运行。
- 当开发结束后，会自动仅剩下一个 AEK 实例。
- 如果你的 AI 不知道这么做，可复制这个 skill 的绝对路径给 AI。

## 什么时候用

- AI 准备改动 AEK 自身的源码、插件、桌面壳或控制台时，先把这段说明交给它。
- 开发过程中需要验证改动又不想打断正在使用的 AEK 时，用 AEK Next 作为隔离实例。
- 开发收尾后，确认只剩一个 AEK 实例，不留孤儿后端进程或重复窗口。

## 两个实例的约定

- `AEK` 是日常使用的实例，保持运行。
- `AEK Next` 是开发用的隔离实例，数据根与 `AEK` 分开，不会污染日常数据。
- 控制台的「运行实例管理」会显示每个实例的 URL、端口、后端服务与桌面窗口状态，并提供复制与启停入口。
- 端口与数据根由宿主从槽位表运行时解析，不要写死在脚本或文档里。

## 给 AI 的最短指令

- 把这个 skill 的绝对路径复制给 AI，让它自行判断是否需要起 `AEK Next`。
- 不要替 AI 决定「直接改当前实例」——保持原实例可用是这套隔离机制的目的。
- 开发完成后让 AI 自己收尾到「仅 AEK」，不要留下双实例长期并存。

## 目录说明

- `assets/` — 预留给以后要附带的模板或静态资源。
- `references/` — 预留给以后要补充的架构说明。
- `scripts/` — 预留给以后要附带的可执行脚本。
